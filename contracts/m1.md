## Contrat de cycle de vie

- `infra/gpu-up.sh` : code 0 seulement après disponibilité du modèle local.
  Entrées : credentials injectés, projet dédié explicitement identifié, zone,
  GPU_INSTANCE_TYPE, coût horaire estimé validé, identifiant du volume persistant,
  configuration de modèle et révision/empreintes provenant du model-gateway.
  Toute entrée obligatoire absente provoque un échec avant création.
- Avant création : écrire coût/h dans BRAIN/STATUS.md et JOURNAL.md ; vérifier
  le périmètre projet, les alertes budget et l'extinction planifiée indépendante.
- Provisionnement par CLI/API documentée et cloud-init, sans installation SSH.
  Monter le Block Storage persistant, vérifier les poids, lancer une image vLLM
  figée avec prefix caching. Réutiliser le volume lors du second cycle.
- Sorties : BRAIN/gpu_ip.txt après readiness ; état local privé avec identifiants
  projet/zone/instance/IP/volume dès leur attribution pour permettre le nettoyage.
  Aucun secret dans ces fichiers ni dans les logs. Aucun état runtime commité.
- Idempotence : réutiliser seulement une ressource dont le projet et l'identité
  ont été vérifiés ; refuser les correspondances ambiguës et étrangères.
- `infra/gpu-down.sh` : détruire instance et IP possédées, conserver les poids,
  attendre et vérifier l'absence des ressources éphémères ; répétition sans effet.
  Échec explicite si l'API est inaccessible ; ne pas assimiler erreur et absence.
- `infra/inventory.sh` : inventaire borné au projet dédié et coût résiduel ;
  exécuté après nettoyage, y compris lors d'un échec partiel.

## Contrat gateway

LiteLLM sur la VM app, URL unique compatible OpenAI, routage défini uniquement
dans services/model-gateway/routing.yaml. Alias public `local`, fournisseur local
vLLM et fallback Generative APIs Scaleway UE ; noms réels dans le gateway.
GET /v1/models retourne HTTP 200 et une liste contenant l'alias `local`.
POST /v1/chat/completions accepte model, messages, max_tokens et stream ;
en mode streaming, événements SSE compatibles et terminaison `[DONE]`.
Les erreurs d'entrée sont HTTP 4xx ; indisponibilité de tous les fournisseurs,
HTTP 503 ; aucune fausse complétion de secours. Authentification injectée,
timeouts et budget serverless explicites ; aucun secret renvoyé au client.
La preuve M1 force le fournisseur local pour éviter qu'un fallback masque une
panne GPU. Le test de panne en plein trafic/UI reste M4.

## Contrat de preuve et critères d'acceptation

Le rapport respecte m1-bench.schema.json et est archivé sous BRAIN/bench/ avec
un artefact CI durable (ce dossier est actuellement ignoré par Git).
TTFT : temps monotone entre envoi et premier contenu SSE non vide ; débit :
(tokens générés - 1) / temps entre premier et dernier token, avec comptage
provenant du fournisseur. Refuser une mesure sans usage ou sans contenu.

1. Depuis un inventaire sans instance/IP GPU, créer et obtenir HTTP 200 via
   le gateway ; générer réellement via le fournisseur local et mesurer TTFT/débit.
2. Détruire et vérifier instance/IP absentes, volume conservé.
3. Recréer avec ce volume, vérifier une nouvelle génération ; chronométrer
   création jusqu'à readiness du gateway : strictement moins de 1200 secondes.
4. Nettoyer et vérifier l'inventaire final, même après erreur ou timeout.
5. Local puis job GitHub `ci` vert avec ces preuves ; aucun succès statique
   ne constitue une preuve de réalisation du cycle GPU réel.
