# Contrat M1 — infra GPU reproductible + gateway (version PoC minimale)

## But
Prouver qu'un nœud GPU se crée par script, sert un modèle via vLLM, puis se
détruit par script. Rien de plus. La rigueur métrologique (TTFT au chunk près,
reproductibilité multi-cycles) est reportée en phase 2.

## Validation
La preuve de M1 est l'exécution réussie de `make verify-m1` **sur la VM** (avec
les credentials Scaleway), PAS un run CI GitHub (qui n'a ni GPU ni secrets).
En CI, `verify-m1` fait un contrôle statique des scripts uniquement.

## Livrables
- `infra/gpu-up.sh` : crée le nœud GPU, monte le volume de poids persistant,
  lance vLLM avec prefix caching activé, écrit l'IP dans `BRAIN/gpu_ip.txt`.
- `infra/gpu-down.sh` : détruit l'instance (conserve le volume de poids).
- `services/model-gateway/` : configuration de routage (local + fallback).

## Ce que `verify-m1` vérifie sur la VM (un seul cycle)
1. `gpu-up.sh` crée le nœud depuis zéro et produit une IP.
2. vLLM répond HTTP 200 sur `/v1/models` (readiness, max 12 min).
3. Une inférence de contrôle sur `/v1/chat/completions` renvoie une complétion
   valide ; on mesure la durée totale et le débit approximatif (tokens/s).
4. Le résultat est archivé en JSON sous `BRAIN/bench/` (format libre : au moins
   `ip`, `total_s`, `output_tokens`, `tokens_per_s`, `ts`).
5. `gpu-down.sh` détruit le nœud.
6. Le cycle complet prend moins de 20 minutes.

Un trap garantit la destruction du GPU en sortie, même en cas d'échec, pour ne
jamais laisser de GPU facturé à vide.

## Hors périmètre M1
TTFT mesuré au premier chunk SSE, second cycle de reproductibilité, conformité à
un schéma strict, exécution GPU en CI. Reportés en phase 2 si le PoC réussit.
