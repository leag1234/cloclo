# M15 — API développeurs locale

Source: docs/15 §M15 ; REQ-MOD-004, REQ-FIN-002, REQ-ENG-002/004.
Références de protocole : developers.openai.com/api/reference/resources/responses,
learn.chatgpt.com/docs/config-file/config-advanced,
code.claude.com/docs/en/llm-gateway-protocol.

REQ-DEV-001 : service FastAPI développeurs distinct, loopback8030, accessible par
SSH. Toutes les routes exigent une clé API aléatoire de256bits minimum ; Bearer
(OpenAI) ou x-api-key (Messages). Deux credentials différents sont refusés.
Identité issue exclusivement de la clé validée ; aucune identité client déclarative
n'est utilisée pour autoriser ou facturer. Clés stockées hachées SHA256 dans SQLite
local0600 ; création/révocation administrateur locale, secret remis dans un fichier
0600 exclusif, jamais stdout. Pas de clé fournisseur remise aux clients.

REQ-DEV-002 : quota quotidien UTC par développeur, en requêtes et micro-euros ;
réservation atomique SQLite avant I/O fournisseur, transactions concurrentes testées.
Solde insuffisant429, clé absente/invalide/révoquée401. Coût réel réconcilié avec
usage fournisseur ; usage absent, timeout, annulation ou redémarrage conserve la
réserve entière. Pas de remboursement spéculatif ni de relance après émission SSE.
GET /v1/usage expose seulement les compteurs du développeur authentifié. Journaux
sans contenu ni clé : identifiant requête/dev, durée, tokens, coût, état.

REQ-DEV-003 : POST /v1/chat/completions, POST /v1/responses et POST /v1/messages
exposent texte et outils fonctionnels fournis par le client. Les outils sont
exécutés exclusivement par le client ; aucun accès au RAG, fichiers, historique ou
MCP partagé de l'assistant. GET /v1/models annonce atlas-code, alias interne sans
identifiant fournisseur. Le gateway choisit son rôle code ; modèles/tarifs restent
exclusivement dans services/model-gateway. Adaptateur UI8020 inchangé.

REQ-DEV-004 : messages multi-tours, appels multiples avec identifiants stables,
arguments JSON fragmentés, résultats d'outils corrélés, tool_choice, raisons de fin,
usage et annulation. SSE réellement incrémental pour texte ET arguments, terminaison
propre suivant chaque protocole. Sortie tronquée marquée length/max_tokens/incomplete,
jamais stop mensonger. Responses sans stockage serveur (store=false), historique
renvoyé par le client ; pas de previous_response_id ni outils hébergés OpenAI.
Messages texte/tool_use/tool_result ; fonctions JSON Schema ; entrées multimodales
ou options non implémentées refusées explicitement, jamais silencieusement ignorées.
Les champs de métadonnées documentés sans effet sont validés séparément.

REQ-DEV-005 : corps borné1MiB, délai120s, contexte limité à la capacité du modèle
ET au plafond0,05EUR par requête. Réservation conservatrice des tokens entrants
(octets UTF8 sérialisés + marge de protocole) et du maximum sortant AVANT transport.
Pas de troncature silencieuse du code. Réponses400 pour contexte/budget/options
incompatibles ; erreurs fournisseur génériques502. Grand contexte de code testé
avec au moins24KiB d'entrée utile ; limites financières publiées, sans prétendre
qu'un dépôt arbitraire tient sous0,05EUR. Pour cette API, une seule tentative code
permet d'allouer le budget au contexte ; aucun changement du fallback du chat M8.

AC-DEV-001 : authentification manquante/invalide/révoquée, clés distinctes, absence
de fuite entre développeurs et quota concurrent/persistant vérifiés sans fournisseur.
AC-DEV-002 : conversation texte→fonction→résultat→réponse, outils multiples, unicode,
arguments fragmentés, erreur/timeout/déconnexion/troncature sur les trois protocoles.
AC-DEV-003 : grand contexte réellement envoyé, contexte et coût excessifs refusés
avant I/O, coût réel par clé et réserve inconnue observables.
AC-DEV-004 : Codex et Claude Code réels, versions figées, réalisent chacun une tâche
synthétique dans un dossier isolé ; tests du résultat exécutés hors modèle. Aucune
clé cloud/GitHub ni configuration personnelle accessible aux clients. Connexion
Claude Code à un modèle non-Claude expérimentale, non prise en charge par Anthropic.

make test-devapi génère les six indicateurs BRAIN/eval/devapi.json après assertions ;
make test-devapi-e2e utilise le vrai fournisseur sous plafond. Preuves synthétiques
expurgées et versions dans reports/M15.md ; fixtures seulement dans tests, CI sans
secret. make verify-m15 protégé inchangé ; invocation ajoutée au lanceur de tests.
Contrat et schéma SQL mergés avant code ; incréments ciblés sous400lignes chacun.
Aucun GPU, aucune exposition publique/HTTPS/UI multi-utilisateur dans ce jalon.
