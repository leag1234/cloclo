# M13 — génération d’image souveraine

Source: docs/15 M13, REQ-ENG-004/009, REQ-INF-012/013, REQ-FIN-002.

Une demande explicite de génération dans le chat appelle le gateway, qui seul
connaît le serveur GPU. Retour : image PNG encodée en data URI dans la réponse
Markdown compatible UI. Description non vide, limitée à 2000 caractères ; filtre
minimal des demandes illicites avant transport. Aucun téléchargement d’image externe.
L’image et sa description ne sont pas enregistrées dans un rapport versionné hors
cas synthétique de vérification. Erreurs explicites, aucun secret dans les réponses.

Le gateway appelle un serveur diffusers sur GPU Scaleway du projet dédié, restreint
à la VM cliente. Modèle Flux configuré dans services/model-gateway. Exécution
séquentielle : le serveur texte éventuel est arrêté pendant la génération puis
rétabli ; le texte PoC actuel reste serverless. PNG 512 × 512, quatre étapes,
une image par requête, verrou exclusif et délai 120 secondes. Coût GPU estimé
sur durée réelle, refus si réservation au tarif constaté dépasse 0,05 EUR.
Le chargement initial des poids est mesuré séparément du temps de requête.

Le déploiement est scripté ; plafond 2 EUR/h, enveloppe totale M13 30 EUR attestée
par MISSION. Nettoyage via infra/gpu.py down dans un finally, même sur échec.
Les poids persistants peuvent être conservés conformément au cycle M1.

make test-imagegen produit BRAIN/eval/imagegen.json à partir d’une vraie génération
GPU et d’une lecture HTTP locale : image_produced, served_locally, dimensions,
durée, coût estimé et empreinte SHA256. Vérification visuelle du cas synthétique
consignée dans reports/M13.md. Aucun drapeau de succès sans génération effective.
make verify-m13 appelle le script protégé intact ; la CI appelle son mode statique
et les tests déterministes sans fournisseur payant.

Plan : serveur GPU et déploiement reproductible ; transport gateway ; routage chat ;
tests de validation, filtre, budget avant I/O, indisponibilité, retour PNG et nettoyage.
Dépendances GPU isolées de la VM/CI, versions figées et justification dans le rapport.
Aucun workflow, verify-* ni CODEOWNERS modifié.
