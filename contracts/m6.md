# M6 — dossier de décision
Exigences : POC-P1..P9, POC-F2/F3/F6, REQ-ENG-004/009/011, REQ-FIN-002.
Contrats existants : Query/Result M3, télémétrie M5, commandes et sortie Markdown
imposées par scripts/verify-m6.sh. Aucun nouveau schéma d'API ou migration.
Plan : filtre pur des contrôles invisibles à la validation Query ; micro-bench
serverless (un appel de référence puis deux vagues de huit), démo RAG/web/fallback
réelle enregistrée, rapport construit depuis ces mesures et les évals M5.
Réservation maximale : 17×0,05 + 3×0,05 = 1 EUR. Aucun GPU.
Les archives sont des mesures, pas des réponses simulées. Le rejeu vit uniquement
dans les tests ; les commandes live utilisent les transports existants.
Le filtre ne prétend pas résoudre l'injection sémantique ; Unicode, tabulation et
retours à la ligne sont conservés. Contrôles C0/C1, surrogates et bidi overrides
sont rejetés avant I/O. Pas de contenu utilisateur dans les logs.
Le rapport garde P7/uptime 14 jours indisponibles si absents, et distingue le
serverless du modèle GPU local. Une absence ou un seuil manqué impose NO-GO ;
aucune valeur n'est inventée pour rendre vert le dossier de décision.
Tests : rejets avant réseau, entrées multilingues inchangées, traces de démo
insuffisantes refusées, absence de mesure => NO-GO ; local puis job ci vert.
