# M7 — chat et observabilité

Exigences : REQ-ENG-004/005/009, REQ-INF-004, REQ-FIN-002 ; POC-F1..F5,
POC-P6, MISSION M7. Contrat publié avant implémentation (R-02).

## API publique locale (port 8020)

- GET /v1/models : liste OpenAI-compatible, alias applicatif `atlas`.
- POST /v1/chat/completions : `model: atlas`, `messages` (1..100 objets
  role system/user/assistant et content texte), `stream` bool optionnel.
  Dernier message user obligatoire ; texte total <=32000 caractères ; validation
  du filtre M6. Les options usuelles de client sont tolérées ; aucun outil fourni
  par le client n'est exécuté. Le serveur garde les budgets POC-P6.
- Réponse : id, object chat.completion, created, model, choices (assistant,
  finish_reason), usage (prompt_tokens/completion_tokens/total_tokens).
  En SSE : objets chat.completion.chunk puis data: [DONE]. La génération interne
  est actuellement atomique ; le SSE transporte la réponse après la boucle.
- Historique fourni par le client conservé dans le contexte ; Open WebUI persiste
  les conversations dans son volume. Annulation client : annuler la boucle bornée.
- GET /sources/{chunk_id} : passage cité résolu par le service retrieval ; 404
  pour une source absente. Les citations rendues renvoient à ce chemin.
- Erreurs JSON typées sans détail fournisseur : 400 entrée invalide, 413 trop
  volumineuse, 502 fournisseur, 504 délai/budget ; aucune exception brute exposée.

## Frontières internes

Le gateway accepte un champ optionnel `local_enabled` bool sur /agent/complete
(défaut historique true). L'adaptateur le fixe depuis GPU_LOCAL (défaut false).
Le gateway retourne, si demandé par `observe: true`, `observation` contenant
provider local/escalade et route simple/complexe. Aucun nom de modèle n'en sort.
GatewayModel accepte cette extension sans modifier le contrat de ses anciens clients.

Le service retrieval expose POST /search {query} : passages chunk_id, doc_id,
source, text, score (score réel du reranker), et GET /sources/{chunk_id}.
Seul retrieval lit sa base. L'adaptateur utilise ce contrat pour rag_search ; les
outils web et le calcul restent ceux du harness, avec leurs protections existantes.
Le modèle décide du choix des outils ; génération et synthèse passent au gateway.

## Journal d'interaction

Une ligne JSON par requête, y compris erreur/annulation, dans
BRAIN/interactions/YYYY-MM-DD.jsonl (répertoire 0700, fichier 0600).
Champs : timestamp UTC, request_id, question, reponse, modele_utilise
(local/escalade ou null avant appel), route_decision (simple/complexe ou null),
latence_ms {retrieval,generation,total}, chunks_recuperes [{chunk_id,doc_id,score}],
citations [{chunk_id,doc_id,source,text}], tokens {in,out}, cout_eur,
erreurs (codes), état. Coût conservateur réservé conservé en cas d'usage inconnu ;
les tokens reçus sont séparés de cette réservation. Les secrets injectés et les
motifs de clés sont masqués dans toute la ligne ; aucun header enregistré.

## Démarrage et validation

make serve démarre gateway CPU, index PostgreSQL/pgvector, retrieval HTTP,
adaptateur et véritable conteneur Open WebUI. Aucun GPU provisionné ; GPU_LOCAL=1
permet uniquement d'utiliser un endpoint local déjà configuré.
Ports liés à 127.0.0.1 ; accès utilisateur par tunnel SSH vers 3000 ; API accessible
à Open WebUI par réseau hôte Linux. Volumes persistants ; arrêt des processus et
conteneurs lancés par la commande, sans effacement des données.

make test-ui : test HTTP intégré avec réponses fournisseur enregistrées, vraie
résolution de citations, journal inspecté, pas d'appel payant CI. Open WebUI réel
est démarré pour verify-m7 et reste joignable jusqu'au contrôle protégé final.
Tests négatifs : entrée vide/géante/Unicode, fournisseur indisponible, timeout,
source inventée, secret dans question/réponse, streaming, historique et budget.
Le workflow protégé invoque make test ; scripts/test.sh peut appeler verify-m7.
