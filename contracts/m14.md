# M14 — client MCP et confirmation des écritures

Source: docs/15 §M14 ; REQ-ENG-002/004/009, REQ-FIN-002.

REQ-MCP-001 : le harness expose un outil optionnel `mcp_call` quand un fichier
administrateur ATLAS_MCP_CONFIG est configuré. Sans configuration, les quatre
outils existants restent identiques. Entrée stricte : server, tool, arguments
(objet JSON, maximum 16 KiB). Serveurs et outils hors liste autorisée refusés
avant toute connexion. Transport MCP stdio, initialisation puis tools/call,
délai total 15 secondes, résultat borné 256 KiB, enveloppe trust=untrusted.
Commandes et arguments viennent uniquement de la configuration administrateur,
jamais du modèle ; aucun shell. Les secrets sont référencés par nom de variable
d'environnement, jamais inclus dans les déclarations d'outils ou les rapports.
Le processus reçoit seulement l'environnement explicitement nécessaire.

REQ-MCP-002 : chaque outil autorisé est classé read ou write par l'administrateur.
Les annotations du serveur ne peuvent pas modifier cette classification. Les
arguments fixes (notamment project_id) sont imposés avant I/O ; leur remplacement
est refusé. Une écriture demandée par le modèle ne fait aucun appel fournisseur :
elle prépare une action immuable, avec identifiant aléatoire et durée dix minutes.
La réponse donne une URL locale de prévisualisation des arguments exacts.

REQ-MCP-003 : seul le POST du formulaire humain de confirmation peut consommer
une action préparée. GET sans effet ; origine et jeton anti-CSRF vérifiés. Ni un
argument confirmed du modèle, ni une instruction du serveur n'autorise l'écriture.
Une action consommée, expirée ou dont la configuration a changé est refusée.
Consommation atomique avant I/O ; aucune relance automatique d'une écriture dont
l'issue est incertaine. PoC UI mono-utilisateur local ; pas d'exposition publique.

REQ-MCP-004 : journal local structuré des noms serveur/outil, état et durée, sans
arguments, contenu ni secrets. Erreurs fournisseur génériques ; stderr du serveur
non transmis au modèle. Un résultat contenant un secret configuré est refusé.

AC-MCP-001 : vraie lecture GitLab via MCP et création d'une issue synthétique après
confirmation explicite. AC-MCP-002 : zéro écriture sans confirmation, refus du rejeu,
de l'expiration et du remplacement de projet. AC-MCP-003 : aucune fuite de secret
dans réponse ou journal, y compris serveur malveillant. AC-MCP-004 : entrées invalides,
erreur fournisseur, réponse géante, timeout et outil inconnu couverts par tests.

make test-mcp produit BRAIN/eval/mcp.json avec les quatre indicateurs du vérificateur
protégé. Tests déterministes en CI ; preuve réelle GitLab conservée séparément dans
reports/M14.md avec contexte et empreintes des échanges synthétiques expurgés.
Les cassettes restent exclusivement dans les tests. make verify-m14 inchangé.

dédiée avec projet synthétique ; aucune donnée entreprise. Coût cloud additionnel
0 EUR/h, aucun GPU ni appel payant MCP. Conteneur limité en RAM et supprimé après

et alternatives documentées avant leur ajout. Implémentation après merge du contrat,
en PR ciblées de moins de 400 lignes, tests et documentation associés.
