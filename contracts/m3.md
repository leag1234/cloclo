# M3 — harness et outils en lecture seule

Source: docs/13 POC-F3/F4/F5, W1..W5, P6 ; docs/06 REQ-HAR-001/002/006,
REQ-TOOL-001/002/004/012/013/014/015 ; REQ-FIN-002.
Contrat et implémentation dans les mêmes PR autorisés par mandat M3.

Entrées d'outils : objets stricts, propriétés supplémentaires refusées.
- calculator : expr, chaîne arithmétique <= 512 caractères ; nombres décimaux,
  parenthèses, + - * / uniquement. Résultat décimal exact, erreur explicite.
- rag_search : query non vide <= 4000 caractères ; recherche via contrat M2.
- web_search : query non vide <= 4000, n entier 1..5 (défaut 5),
  lang fr/de/es/it/en, news booléen (défaut false). SerpApi Google/News,
  localisation par langue ; titre, URL, snippet et date disponible.
- web_fetch : url HTTP(S) publique, sans identifiants, <= 4096 caractères.
  DNS et redirections validés, connexion épinglée à une IP publique ; robots
  fail-closed, timeout <=15s, corps <=2Mo ; trafilatura, 8000 tokens maximum,
  handle local pour la suite, cache 24h. Texte non fiable, URL et date UTC.

Requête harness : question non vide <=32000, langue explicite parmi cinq langues.
Budget configurable uniquement à la baisse : 10 outils, 120s, 0.05 EUR,
16384 tokens (choix opérationnel M3 ; POC-P6 ne chiffre pas les tokens).
Réservation coût/tokens avant I/O, timeout borné par deadline globale. Aucun appel
payant sans tarif configuré ; timeout n'annule pas une facturation déjà engagée.
Maximum 3 recherches, 8 fetches ; répétition identique trois fois : arrêt.
États : model, tool, done, stopped. Sortie : texte, raison d'arrêt, trace,
consommations et références. Erreurs typées visibles du modèle, jamais avalées.
Recherche : cache 1h, quota mensuel persistant, refus à 900 recherches réservées
sur 1000 ; les échecs peuvent conserver leur réservation (borne conservatrice).

AC : schémas/arguments invalides, calcul exact et attaques, IPv4/IPv6 privées,
DNS mixte/rebinding/redirections, robots, tailles/deadlines, caches/quotas,
quatre arrêts budgétaires en intégration ; traces E4 >=90%, E6 bout en bout.
Les fournisseurs sont enregistrés réellement pour replay sous tests uniquement.
Les clés draft et le juge non calibré ne constituent pas un GO qualité E6.

Plan complet : BRAIN/m3-plan.md. Périmètre M3 seulement, aucun GPU ; coût cloud
additionnel 0 EUR/h. PR par incrément si nécessaire pour REQ-ENG-008 (<400 lignes).
Fichiers protégés inchangés. CI du SHA exact requise avant chaque merge.

Gateway (même URL que M2) : POST /agent/config avec {} retourne uniquement
input_eur_per_mtok, output_eur_per_mtok et max_tokens (2048). Tarifs fournis
humainement dans services/model-gateway/pricing.yaml, aucun identifiant exposé.
POST /agent/complete : {messages: liste d'objets <=100, tools: liste <=4,
timeout: secondes <=120}. Réponse {text, usage:{prompt_tokens,completion_tokens}, calls:[{id,name,arguments}]} ; erreurs
provider_error/invalid_input, jamais de réponse fournisseur brute en erreur.
Réservation initiale conservatrice : nombre d'octets JSON UTF-8 + 256 tokens de framing,
plus 2048 tokens de sortie ; coût calculé avec ces bornes. Après réponse complète, réconciliation avec usage fournisseur validé inférieur à la réservation. Timeout/erreur conserve toute la réservation.
SerpApi Starter : abonnement fixe, quota dur 900 recherches/mois ; coût marginal
nul dans le forfait, aucun dépassement payant autorisé. Coût fixe suivi séparément.

Extraits initiaux : web <=2000 octets UTF-8 (reste derrière handle), RAG <=400
octets par passage (chunk_id résout le passage complet M2). Plafond 8000 tokens
conservé, limites plus basses pour laisser de la place aux itérations.
API harness locale POST /query (Query) ; GET /continuation/{handle}?offset=0
retourne texte non fiable et next_offset ; handles expirés 404. Aucune écriture externe.

Après chaque réponse valide, le compte prompt_tokens fournisseur du préfixe exact
est réutilisé ; seuls les nouveaux messages sont réservés en octets UTF-8 + 256
tokens de framing, plus la sortie maximale. Si le préfixe change, revenir à la
borne complète. Les limites cumulées restent identiques ; usage supérieur à la
réservation provoque provider_error. Tests de préfixe modifié et coût cumulatif.

Clés humaines 037fbd5/b95e11f : E4 accepte le refus SSRF en amont ou par
l'outil (aucun contournement), la normalisation URL avant fetch ou après erreur,
et l'arrêt explicite anti-boucle. La recherche publique de comparaison est
recommandée, non bloquante. E6 exécute uniquement les cas statut `valide` ;
les emplacements draft et stale ne sont pas exécutés. Aucun GO qualité revendiqué.
