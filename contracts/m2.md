# M2 — proposition de contrat et plan, à revoir avant implémentation

Source: POC-F2/A3, POC-E1/E2/E3, REQ-ENG-002/004/009/011,
REQ-FIN-002 ; docs/11 R-02 et §9.2 ; scripts/verify-m2.sh (lecture seule).

## Contrats proposés

- `make ingest` lit corpus/, extrait pdf/docx/md/html et persiste les chunks
  dans Postgres + pgvector. Réingestion identique idempotente, transactionnelle.
- Chunk : chunk_id stable, doc_id, langue, source locale, texte non vide,
  position dans le document, empreinte source, embedding fini de dimension
  constante ≤ 1024. Un changement de contenu invalide les anciennes citations
  explicitement ; un identifiant inconnu ne résout jamais vers un autre passage.
- Recherche : entrée question non vide et k entier entre 1 et 8 ; sortie liste
  ordonnée sans doublons de chunks avec scores. BM25 + embeddings multilingues
  + fusion puis cross-encoder. Seule la question entre dans le retrieval : ni
  doc_id_attendu ni passage_attendu ne sont accessibles à ce chemin.
- Génération via gateway uniquement : question + passages récupérés ; sortie
  texte et citations chunk_id, chacune appartenant aux passages récupérés.
  Les prompts résident dans prompts/, les modèles dans services/model-gateway/.
  Refus explicite si sources insuffisantes ; erreur typée sur citation inventée.
- Résolution chunk_id : passage et métadonnées exacts persistés, ou erreur
  explicite introuvable. Aucun lien source arbitraire exécuté par ingestion.
- `make eval-retrieval` produit BRAIN/eval/retrieval.json conforme au schéma
  adjacent. Recall = moyenne des cas dont doc ET passage figurent dans top-8 ;
  MRR = moyenne de 1/rang, zéro si absent. Ventilation par langue obligatoire.
  citations_resolues est vrai seulement après génération de réponses non vides
  et résolution effective de toutes leurs citations ; zéro citation échoue.
  Les drafts restent indicatifs et ne constituent pas un GO qualité validé.

## Plan d'implémentation après revue et merge humains

1. Compléter les questions E1 manquantes sans changer les clés attendues ;
   annoter les brouillons genere-a-valider/draft, conserver les cas existants.
2. Tests rouges de contrats, extraction quatre formats, Unicode (AR/ZH inclus),
   vide/corrompu/trop volumineux, idempotence, persistance et suppression.
3. Ingestion et index dans services/retrieval ; migration réversible testée.
   Embeddings/reranker CPU derrière gateway, sans GPU ni appel LLM live en CI.
   Dépendances à justifier (licence, taille, maintenance, alternatives) dans la PR.
4. Tests retrieval avec distracteurs, séparation questions/clés, scores réels,
   puis génération et citations avec cassettes enregistrées dans les tests.
   Tester erreurs fournisseur, timeout, citation inconnue et contexte dépassé.
5. Makefile, scripts/test.sh et evals/harness.py intègrent le gate M2 au job ci
   existant sans toucher aux fichiers protégés ; pas de récursion des gates.
6. Mesurer couverture du diff ≥ 80 %, logs structurés, latence et coût ;
   documenter service/runbook/SLO, preuves rouges et limites de validation.
7. make verify-m2 local puis branche/PR, attendre ci vert, actualiser BRAIN,
   arrêt M2. Découper en PR < 400 lignes, merges uniquement humains.
