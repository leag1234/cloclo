# M16 — English localization

Requirements: MISSION M16, REQ-ENG-008/011, REQ-FIN-002.

The public repository now has a project README with an architecture overview,
installation and serving instructions, SSH access, milestone summary, and license
note. Public requirements, contracts, runbooks, service documentation, comments,
and user-facing messages are translated into English.

Translations are produced directly as complete files, sequentially, and reviewed.
Each file or small group has its own English commit. No segmented transport,
numbered lines, translation cache, or invariant-validation pipeline is used.
This localization is delivered together in one milestone PR as requested; its
file-by-file commits provide review boundaries for the documentation-wide change.

Runtime identifiers, API fields, enum values, filenames, and multilingual routing
expressions retain their existing meaning. Corpus and golden evaluation data are
not translated. Synthetic multilingual test inputs remain in their original
languages. One expected runtime refusal in a test cassette is translated; the
recorded provider response and the exact equality assertion remain unchanged.

The project UI labels and document language are English. Its request parameters,
including the existing document language value, retain their previous behavior.
No product provider prompts, budgets, thresholds, or authorization rules are changed.
Protected workflows, verification scripts, and CODEOWNERS are untouched.
The existing test launcher invokes the protected M16 gate in GitHub CI.

Local verification: lint, type checking, 302 unit/integration tests, secret scan,
the four project UI tests, and `make verify-m16` (exit 0). The protected M16 verifier rejected the partially
translated documentation during implementation. Final milestone completion is
established by the GitHub `ci` check on the PR delivering this report; local
results alone are not completion evidence.
