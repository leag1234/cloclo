# M11 — streaming progressif, validation en cours

POC-F1/F5, POC-P6, REQ-MOD-004, REQ-FIN-002. Contrat préalable #49
fusionné après CI verte : https://github.com/leag1234/cloclo/actions/runs/34507795404.
Cette CI prouve le contrat seulement ; M11 n'est pas encore terminé.

Le gateway décode le flux fournisseur UTF-8, valide usage/fin/DONE et assemble
les arguments outils. L'adaptateur transmet immédiatement les deltas via une
queue bornée à huit événements. Le trajet streaming emploie l'escalade serverless,
sans GPU ni relance après émission. La politique M8 choisit la route avant I/O
et réserve le fallback éventuel dans le budget de 0,05 EUR.
La réflexion fournisseur est séparée dans reasoning_content, désactivée par défaut,
activable avec reasoning_effort=low, sous le plafond commun de 2048 tokens.
Les métadonnées atlas indiquent tour, phase provisoire/intermédiaire/finale,
réservation et coût. Une mention visible « Étape intermédiaire » distingue aussi dans Open WebUI
le texte précédant un outil de la réponse finale.

make verify-m11 exécute une barrière sur deux connexions HTTP réelles : le client
reçoit le premier fragment pendant que le fournisseur contrôlé attend encore
l'acquittement avant le second. Le rapport BRAIN/eval/streaming.json contient
le nombre de fragments, la preuve de progression, le coût et la durée mesurés.
Ce test est déterministe et sans appel payant ; ce n'est pas un benchmark Scaleway.
Les tests couvrent également réservation avant I/O, usage manquant, Unicode,
réflexion séparée, appels outils, fermeture, client lent et citations fragmentées.

dans la requête chat ; la valeur par défaut est `none`. Les tokens de réflexion
sont inclus dans completion_tokens et dans le même plafond de coût, sans
réservation additionnelle. Le rapport du test contrôlé contient un coût calculé
sur son usage synthétique ; il ne représente aucune dépense fournisseur réelle.
